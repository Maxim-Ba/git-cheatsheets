# 01. Одно ФИО и одна почта

## Типичная картина (пример)

Один и тот же человек в истории репозиториев выглядит как четыре разных автора:

| Подпись в коммитах | Откуда, скорее всего |
|---|---|
| `Ivan Petrov <ivan@personal.example>` | глобальный конфиг одной машины |
| `ipetrov <i.petrov@company.example>` | другая машина / рабочий конфиг |
| `ipetrov <12345+ipetrov@users.noreply.example>` | коммиты, сделанные через веб-интерфейс хостинга (merge request'ы) |
| `Petrov Ivan <ivan@personal.example>` | третий вариант написания имени |

Проверить у себя в любой момент: `scripts/audit-identity.sh <папка с репозиториями>`.

## Решение (нужно принять один раз)

Выберите **одно имя** и **одну почту**:

- Имя: например `Ivan Petrov` (латиницей, один порядок слов). Логин на хостинге — это
  имя аккаунта, а не ФИО, как подпись он лишний.
- Почта — три варианта:
  1. **Рабочая** — если проекты рабочие и вы хотите, чтобы вклад числился за работой.
  2. **Личная** — если репозитории личные или вы не хотите светить рабочую почту.
  3. **noreply хостинга** — публично нейтральна и всегда привязана к аккаунту, но подпись почты
     в веб-интерфейсе и в локальном git должна совпадать (иначе опять два варианта).
- Одна почта должна быть **подтверждена в профиле хостинга**, иначе коммиты не привяжутся к аккаунту.
  Точный путь в настройках профиля проверьте в самом интерфейсе.

Правило: не смешивайте рабочую и личную почту в одном репозитории. Если нужны обе — см. «includeIf» ниже.

## Применить на машине

```powershell
# Windows
.\scripts\setup-machine.ps1 -Name "Ivan Petrov" -Email "you@example.com"
```
```bash
# Linux / macOS / Git Bash
./scripts/setup-machine.sh --name "Ivan Petrov" --email "you@example.com"
```

Скрипт выставит `user.name`/`user.email` глобально и подключит общий `~/.gitmailmap`.
Сначала запустите с `-DryRun` / `--dry-run`: он покажет, что изменится.

## .mailmap: как «склеить» старую историю, не переписывая её

`.mailmap` меняет только **отображение** в `git log`, `git shortlog`, `git blame` и в веб-интерфейсах,
которые его читают. Хеши коммитов не меняются — безопасно для уже запушенных веток.

Формат: `Правильное Имя <правильная@почта> Имя в коммите <почта в коммите>`

Готовый шаблон — [templates/.mailmap](templates/.mailmap). Два способа подключения:

- **Глобально** (скрипт делает именно это): файл `~/.gitmailmap` + `git config --global mailmap.file ~/.gitmailmap`.
  Работает во всех репозиториях на машине, ничего не нужно коммитить.
- **Для команды**: положить `.mailmap` в корень репозитория и закоммитить. Удобно, если
  историю читают и другие, но тогда ваши почты окажутся в репозитории (они там и так есть в коммитах).

Проверка: `git shortlog -sne` — должна остаться одна строка на человека.

> Переписывать историю (`git filter-repo`) ради имён не стоит: придётся делать force-push
> в общие репозитории, а коллеги получат расхождение веток. `.mailmap` достаточно.

## Если нужны две почты на одной машине (includeIf)

В `~/.gitconfig`:

```ini
[user]
    name  = Ivan Petrov
    email = personal@example.com

[includeIf "gitdir/i:~/work/"]
    path = ~/.gitconfig-work
```

`~/.gitconfig-work`:

```ini
[user]
    email = work@example.com
```

Все репозитории под `~/work/` будут подписываться рабочей почтой, остальные — личной.
Слеш в конце пути обязателен. На Windows путь пишется с прямыми слешами: `gitdir/i:D:/work/`.
Проверка в репозитории: `git config user.email`.

## Как проверить, что всё применилось

```bash
git config --global user.name
git config --global user.email
git config --global mailmap.file
git log -1 --format='%an <%ae>'      # автор последнего коммита
```
